### What the log says, in order

Your run is in `~/Library/EchoJay/logs/echojay-0.log`, run key `7272e523-0a37-40ce-a0bf-897a3ea0837e`:

| time | line | what it means |
|---|---|---|
| 09:23:52 | `EJAgentHome: opened the run's record, key=7272e523…` | the card exists, on the **processor's** replay list |
| 09:25:13 | `EJAgentRow: the window is going while a run is live - the card is written down and the RUN CONTINUES` | the window went mid-run |
| 09:25:20 | `EJChatLog: rendered chat 1792657430720 … 2 entr(ies) … 1 of them held by the processor and **not yet in the store**` | the card had never reached the stored log |
| 09:25:20–28 | five `EJAgent: step … DONE undo=add:…` lines | the build landed with no window — that half worked |
| 09:26:59 | `EJStores: **dropped 1 unsynced row(s)** that belong to chat 1792657430720, NOT to 1792608733685` | the card was thrown away on a chat switch |

So: the run applied, the card was written down **only** on the processor's replay list, and the first
chat switch dropped that list. Nothing had ever written it to the chat you reopened.

### The cause, which is structural

The chat store was **a member of the editor** (`EchoJayWorkspace workspace { api };` in
`PluginEditor.h`). A run's card was appended to it by the window, at the **end** of the run — and
the end-of-run recorder has a second gate: it returns early unless the run has a closing, which a
run interrupted mid-build does not have yet. Put together: a run that finished while no window
existed had **nowhere to write and nobody to write it**.

Your instruction was to fix it at the cause, "through the single stamp (the store appends first,
with no window involved)". A stamp cannot append to a store that does not exist, so:

1. **The store moved to the processor.** `EchoJayProcessor::workspace`, a plain value member; the
   editor now holds a reference to it. This is the move `EchoJayAPI` made on 15 Oct for the same
   reason, with the same lifetime guarantee (JUCE destroys the editor before the processor), and the
   editor's ~200 `workspace.` call sites are untouched. Its constructor does no work and starts no
   timer, so owning it costs nothing until something loads or appends.
2. **The single stamp appends the card.** `appendChatEntry` — the one door every processor-side row
   goes through — now writes a run's card into the stored log of **its own** chat, at the moment the
   record is opened. A card only: a plain row's writer is the send path, which already appends to the
   store first, and two writers for one row is the duplicate fault (DUP2) you had in August.
3. **The run's snapshot keeps the stored copy in step**, by the run's **key**, on every change — so
   a window opening at any moment renders from the store rather than from a list.
4. **Nothing is dropped any more.** The chat-switch site still refuses to carry one chat's rows into
   another (your rule 2, 18 Oct) — but a card that names its own chat is now written **home** before
   the list is cleared.
5. **One hole I opened and closed in the same round:** the end-of-run recorder matched its own row by
   *prose*. With the card now stored at birth, a closing that settled to different words would have
   missed it and appended a second copy. It looks the row up **by the run's key** first.

### What proves it

- **`chat_store_guard`: GREEN, 100 assertions**, six of them new (NW1–NW6) and all driven with **no
  editor at all** — the fault's own condition, which was unwritable before the move:
  the card is in the stored log found by the run's key; the **store** gives it its place when the
  processor has no seq allocator; the steps travel, not just a sentence; a later round **updates that
  one row** rather than adding a second; a card for a chat the store does not hold invents no chat
  (your rule 1); and a plain row is still not store-appended by the stamp.
- **The rig now asserts your sentence** instead of internal state — see §3.

## 2. Your B3 ruling, from this morning

> *"If the user has already pressed Go, a run with no window open finishes its build and applies it.
> The card, its chips and Undo all are there when a window reopens. If the run is waiting on a chip
> or a question, it keeps waiting."*

A windowless build used to **park**: it waited two minutes for a window and then said it had built
nothing. It applies now, by **the road every agent `add` already takes** on the processor
(`ChainHost::applyChainEdits` for the open rack, `writeChainEditCommand` + the ack for a Link) —
which is the move your 19 Oct ruling made for the Build button on a Link, arriving where it was
always going. The park machinery is gone.

Three things found while doing it:

- **The conversion dropped `dial_on_playback`.** A build becomes replace-ops, and the old conversion
  never carried that field — so a windowless loudness build would have landed a limiter with nothing
  measuring it, exactly your 21 Oct mix bus at −5.7 against −8.
- **A windowless build would have been the one road with no recovery.** The window road archives the
  rack before replacing it; this one now does too.
- **The rack's slot count was only published by the editor**, so "did it land while no window
  existed?" could only be read after a window came back. The processor publishes `procSlots` now, and
  `agentLastBuildRoad` ("window" / "processor") names the road a build took.

`agent_round15_guard`: **GREEN, 132 assertions**, ten new (BW1–BW7), including BW2c — which runs the
*replaced* conversion on the same input in the same binary and shows it dropping the dial, so BW2 is
falsifiable rather than a wish.
