## 5. Things that will bite the next session

- **`ui_guard` SIGSEGVs at startup** in a session with no window server - at HEAD, with no local
  change. It is the only guard that instantiates the whole editor. That is why the ask-shelf maths
  was extracted; anything else needing it has the same problem.
- **`mapfps_sync_guard` and `linkmixer_test` are script-based ctest entries, not CMake targets**, so
  they cannot be named as `quick.sh` guards. Run `tools/<name>/build_and_run.sh`, or ctest.
- **`mapfps_sync_guard` refuses while Logic is open** (exit 138, "LIVE-STATE FINGERPRINT CHANGED"):
  the plugin writing its own log counts as live state. Verdict void, not red.
- **A guard binary in `build-guards/guards/` can be hours old.** I read a GREEN from one that
  predated the leg I was testing by twelve hours; the tell was that the leg's own assertion lines
  were missing from the output. **If a leg's lines are not in the output, the verdict is not about
  the leg.**
- **Never edit a source while a build or guard run is in flight** - a verdict about a half-edited
  tree costs a whole cycle to disprove.
- **Place a leg by verified line number, not by text-anchoring on a nearby printf.** That shortcut
  put one leg outside `main` (compile error), one in a neighbouring leg's scope (compile error), and
  one INSIDE `check()` - which compiled and recursed until the stack died (Bus error). Print the
  surrounding lines and confirm the nesting before building.
- **Read the target guard's own idioms first**: `chat_store_guard` names `ChatMsg` only inside its
  friend struct; `agent_executor_read_guard` runs on fakes and cannot build an `EchoJayProcessor`;
  `level_slot_guard` must reference a device's TU or the static registrar never links (that is what
  "MB0: NOT registered" meant about a device that is registered perfectly well).
- **A raw string's default delimiter breaks on B's labels**: `"DPR-402 (s)"` contains `)"`, which
  closes `R"( )"` early. Use `R"JSON( )JSON"`.

## 7. dial_on_playback (B's contract of 20 Oct) — built 14:50

B's field, on an agent `do add`/`replace` beside `settings_structured`:

```json
"dial_on_playback": { "target_gr_db": 3, "control": "Peak Reduction", "rule": "..." }
```

Translated into a **calibration block**, not given a mechanism of its own, because the contract's own
last line says the machinery is already there: *"Agent off already sends a target block (gr_target_db
with calibration), which the plugin dials during playback. No change is needed there."* That road
waits for audio, seeks the band, says nothing on the way in (`Purpose::buildHold` leaves `askOwed`
empty, which `startCalibFromBlock` forces) and closes when it lands — which is what "like the slot-OUT
match" asks for. A second road to the same place is how two of this week's defects happened.

The composer is `CalibLoop::blockFromDialOnPlayback` in `Source/EJCalibLoop.h`, beside the parser that
reads the shape back, for the reason written on `configFromBlock`: both binaries compile that file and
a shape built in two places is two shapes. It is also the only way the translation could be asserted —
the Link's call site needs a hosted rack and a running transport.

**Three fields that are not one-to-one.** Each of them looks right and is not:

1. **`gr_target_db` is a BAND on the wire.** `configFromBlock` reads it with `.getArray()`, so a
   scalar leaves the *default* band in place and the target is silently lost. The band whose prose has
   always been "3 dB" is the non-bus default `[2, 3]`, so **T becomes `[T-1, T]`** and the existing
   wording stays true. Legged at 6 dB rather than 3, because at 3 the bug and the right answer
   coincide — which is how it would have shipped.
2. **The direction is not in the field.** The 28 Sep ruling is that which way a control makes a
   compressor work harder follows from *what the control is*, and is never guessed from its name (that
   ruling exists because a block declaring the MC 77's "Input" a threshold made "ease off" compress
   harder). So: a control whose name says threshold **is** a threshold, lower-is-harder, and is
   stepped — that covers B's `"Threshold"` and the EchoJay Compressor's `threshold_db`. **Anything
   else — including B's own example, an LA-2A `"Peak Reduction"`, where higher is harder — goes in as
   actuator `"amount"`, which the parser turns into hold-and-check**: it measures the slot against the
   target, writes nothing to the plugin, and does not fall through to driving EchoJay's own input. The
   control is named in the log every time. **Owed from B: the control's sense (or actuator) on the
   field.** Until then the common case measures rather than dials, out loud.
3. **`makeup_cap_db` = T**, which is B's own documented default: the hold may not hand back more gain
   than the compression took away.

**One writer per control.** The calibration hold writes this slot's OUT (the 29 Sep ruling — EchoJay's
own OUT, never the plugin's output), and so does the slot-OUT match the same build armed four
statements earlier. Two loops writing one control, each measuring the other's write, is the 21t-m
failure. So the match **stands down** when a dial starts, for the same reason an explicit `slot_out`
command stands it down: something else owns this slot's level now.

**The cost, stated:** a dialled slot does not get the 09:24 measured peak ceiling, which the hold has
no notion of. Owed.

**Also guarded:** the slot is the one `nameTheMatchTarget` resolved **by identity** this batch, and it
is only trusted when `pushIsBuild` — a member read on a non-build push would dial whatever the *last*
build added, and a stale pointer is worse than no pointer (the 2 Oct `remapBlocksToIdentity` lesson).
Every way it declines to start prints a reason, because the contract's fallback — the slot keeps the
gentle start the add carried — is only honest if it is said out loud.

**Leg:** `level_loop_guard` section (17), five parts: (a) a threshold composes and parses back to a
stepping loop with the band `[2, 3]` and the cap; (b) RED-first, the scalar shape loses the target;
(c) an unstated direction holds-and-checks, is never the drive, and names the control in the reason;
(d) `threshold_db` is a threshold; (e) the four ways nothing starts, each with a reason.
