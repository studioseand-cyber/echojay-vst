## Item 6 — the Phase B fallback (no code; for a later build)
**When the lexicon nominates nothing, measurement nominates.** The 205 "ok, no record" rows are modes that found no name
and did not open the pool. Proposal: a mode with zero nominees opens the unnamed pool (the same 40-control cap, meters out)
and runs the role's cheapest two-position process on each — the signature that already decides "unnamed" decides the
nominee: an EQ band = a control whose response shows a peak/shelf (`eq_gain` signature); a drive = THD rising ≥ 3 dB
(`drive`); a limiter ceiling = a control that moves the peak and holds against a 6 dB drive change (`ceiling`); a delay time
= onset moving (`time`); a transient = the hit's first 10 ms moving alone. Cost: ~pool × 2 processes (~1–3 min a product)
on 205 products ≈ 4–6 h — one more night. **Marking them to re-run:** a finished row is never re-run, so the batch writes
the reason into the row (`outcome: ok, records: [], why: "nothing nominated"`) — it does already — and `--phaseb-all
--redo nothing_nominated` deletes exactly the rows whose `records` is empty and whose `why` matches, then runs them again;
`--phaseb-status` lists how many such rows exist per category. Nothing else is touched; the morning zip picks them up as
new files.
